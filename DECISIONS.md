# Решения

| Что решали | Варианты | Выбор и причина | Если неверно |
|---|---|---|---|
| Момент признания платежа | Создание / фактическая оплата | `paid_at` не позднее даты отчёта; очередь показывается отдельно. Это отчёт о деньгах, которые уже ушли. | При учёте обязательств по очереди изменится сумма оплаченного и остаток. |
| Возвраты | Исключать всегда / по дате возврата | Вычитаем только с даты `refunded_at`, включая этот день. До этого деньги у подрядчика. Возврат полный, частичных возвратов формат не содержит. | Исторические срезы и распределение аванса изменятся. |
| Состояние работ | Текущий статус / события на дату | Принятие и отмена действуют с указанных дат, до них работа planned. Договор включается с даты подписания. | Изменится список работ, доступных для оплаты, и актуальная цена. |
| История состава и цены | Исключить будущие работы / использовать известный состав | У работ нет даты создания и истории цен; предполагаем, что состав и цены известны с подписания. | Ранние отчёты могут содержать ещё не согласованные работы или неверные цены; потребуются история изменений и даты создания. |
| Прямые платежи | Приоритет / общая сумма | Платёж с work_id остаётся у этой работы, в том числе плановой. Назначение текстом не меняет привязку; иначе пришлось бы угадывать. | Изменятся суммы по работам, чистая сумма договора сохранится. |
| Общие платежи | FIFO / пропорционально / на все работы | Сначала целевые платежи, затем общий аванс по принятым работам в порядке completed_at, при равенстве по work_id. До цены каждой работы. Остаток не распределяем на непринятые работы. | При пропорциональном подходе или раннем распределении на планы суммы по работам и свободный аванс изменятся; чистая сумма договора нет. |
| Перерасчёт | Исторически закреплять распределения / пересчитывать снимок | Пересчитываем снимок на каждую дату из действующих платежей и работ; нет журнала распределений. Более поздний целевой платёж может освободить аванс, возврат — изменить прошлое распределение в новом снимке. | Если бухгалтер требует неизменяемые проводки, необходим журнал распределений и правила сторнирования. |
| Отмена и переплата | Переносить автоматически / оставлять целевые деньги | Отмена обнуляет эффективную цену; прямые деньги остаются привязанными и отображаются как excess. Перенос возможен только по отдельному решению бухгалтера. | Если допустим перенос, уменьшится свободный долг по другим работам и excess. |
| Итоги и остатки | Один баланс / несколько показателей | Исходная сумма договора не заменяется суммой работ. Показываем остаток по всем работам, долг по принятым, свободный аванс и чистый баланс договора отдельно. | Если отмена не снижает обязательство по договору, чистый остаток нужно рассчитывать по договорной сумме. |
| Деньги и ошибки данных | Float / целые копейки; пропуск / остановка | Целые копейки, не более двух знаков; проверяем ID, связи, даты и статусы. При противоречии останавливаемся, не выдаём частичный расчёт. | При другом формате понадобится явное правило округления и обработка корректировок. |
| Вывод | Консоль / CSV | Два CSV для бухгалтера, CLI без зависимостей. | Меняется слой вывода, не расчёт. |

Формат не содержит частичных возвратов, отрицательных корректировок, истории цен, повторных принятий и отмен принятых работ. Эти ситуации не моделируются без дополнительных данных. Долг по принятым работам — расчётная оценка, не юридическая дата наступления обязанности по оплате.
